# اتصال Nava به ربات ولت (Wallet) — Nava فقط «کلاینت» است

از v1.21 به بعد Nava خودش API ورودی ندارد. Nava به API ولت درخواست می‌زند و فقط وقتی ولت پاسخ **COMPLETED** بدهد، دقیقاً `amount` (نه `total`) را یک‌بار به XP کاربر اضافه می‌کند.

## متغیرهای محیطی (فقط روی Vercel؛ هرگز داخل کد/لاگ/URL)
| نام | معنی |
|---|---|
| `WALLET_API_URL` | آدرس پایه‌ی API ولت (فقط HTTPS) |
| `WALLET_INTEGRATION_ID` | شناسه‌ی اتصال |
| `WALLET_API_SECRET` | کلید مخفی |

## درخواست‌ها
هدر هر درخواست: `Authorization: Bearer <INTEGRATION_ID>.<SECRET>`، `X-Wallet-Timestamp` (ثانیه‌ی یونیکس)، `X-Wallet-Nonce` (۳۲ کاراکتر hex، **برای هر درخواست حتی تلاش مجدد جدید**).

* `POST /transfers` — بدنه: `idempotency_key`, `external_user_id`, `wallet_token`, `amount`, `metadata.note`. تلاش مجدد همیشه با **همان** کلید idempotency.
* `GET /transfers/{id}` — پیگیری وضعیت. فقط `COMPLETED` یعنی XP واقعاً جابه‌جا شود؛ `FAILED` یعنی ناموفق؛ بقیه (`PENDING`, `PROCESSING`, `REQUIRES_RECONCILIATION`) یعنی منتظر بمان.

## جریان داخل ربات
۱. کاربر «💳 انتقال XP از ولت» را می‌زند، مبلغ و توکن ولت را می‌فرستد (پیام توکن پاک می‌شود).
۲. ردیف `wallet_deposits` ساخته و درخواست به ولت فرستاده می‌شود.
۳. ربات تا حدود ۱۵ ثانیه وضعیت را چک می‌کند؛ اگر هنوز تمام نشده، دکمه‌ی «🔄 بررسی وضعیت» می‌آید.
۴. cron روزانه‌ی `process-broadcasts` واریزهای معلق را جاروب می‌کند.
۵. اعتبار با شناسه‌ی دفتر `walletdep:<txId>` فقط یک‌بار ثبت می‌شود (چند بررسی هم‌زمان = یک اعتبار). اگر مبلغ برگشتی با مبلغ درخواست نخواند، اعتباری داده نمی‌شود و به مالک اطلاع می‌رسد.

پنل مالک «🔌 اتصال ولت»: وضعیت متغیرها (بدون نمایش راز)، روشن/خاموش، بررسی انتظارها.

## محدودیت‌های صادقانه
تست‌ها با ولتِ شبیه‌سازی‌شده انجام شده‌اند (قالب هدر، تلاش مجدد، یک‌بار اعتبار، تطبیق مبلغ)؛ با ولت واقعی تست نشده.
